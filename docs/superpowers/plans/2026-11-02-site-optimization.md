# 网站体验与发布质量收口计划

**目标：**改善四刊目录、正文衔接、首页续读、数据加载及发布检查，并为真正的访问控制提供可执行迁移方案。

**现状：**静态 HTML/CSS/JS 站点部署于 GitHub 与 Cloudflare Pages。用户已同意按上一轮五项建议实施。现有前端密码门不是可靠的访问控制；Cloudflare 与 GitHub 账户状态需另行核实，不能在缺少服务端配置时贸然替换线上入口。

## 任务

- [x] 将年份、期次、文章、搜索和收藏卡片改为键盘可操作的原生控件或等效语义，并验证展开状态与焦点代码；触控待真机复核。
- [x] 正文导航在跨期时标明上期或下期，保持现有文章浏览顺序。
- [x] 正文阅读进度只计算文章本身，进度环、续读百分比和恢复位置使用同一终点，不计入相关阅读与页面尾部留白。
- [x] 首页仅在有有效阅读记录时显示紧凑的继续阅读入口，点击可恢复到原文章。
- [x] 正文优先按期加载；全站 Markdown 路径索引只在期次数据失败时作为备份加载。
- [x] 增加 CI 对数据、搜索索引、样式构建、JS 语法和阅读进度的检查。
- [x] 查明访问控制迁移条件并准备 Cloudflare 全站保护指引；仓库目前公开、无可用 GitHub 认证，服务端规则尚未配置。
- [ ] 运行必要验证、复核变更并更新交接记录；如 GitHub 凭据与网络可用则推送。

## 重点验收

目录和搜索项能用 Tab 与 Enter 操作；展开状态可感知。正文跨期按钮文案准确。首页没有记录时无额外内容，有记录时入口可达对应文章。首次进入杂志不请求全站文章路径索引，打开文章仍能读全文。CI 在数据或生成资源不一致时失败。
