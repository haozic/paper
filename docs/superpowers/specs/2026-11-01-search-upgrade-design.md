# 检索能力升级设计（跨刊标题检索 + 正文搜索降本）

> 设计基线：`e2d9a0d`　　设计日期：2026-11-01
> 本文是**设计文档**，实施前不改任何代码。
> 前置文档：`docs/UX_MODERNIZATION.md`（第一至六批已实施）、`docs/CHROME69_COMPAT.md`（兼容性约束）

---

## 一、背景与目标

站点当前功能密度已经很高：排版参数可调、上下篇导航、相关阅读、阅读位置、离线阅读、按期分片正文都已落地。
`docs/UX_MODERNIZATION.md` 里 P0 至 P2 全部条目均已实施，仅「补发布日期」「每期封面」被需求方明确排除。

本轮聚焦**检索能力**，目标三条：

| 编号 | 目标 | 可验证的完成标志 |
| --- | --- | --- |
| G1 | 能跨三刊检索标题 | 首页或杂志内输入一个词，一次看到三刊命中的文章 |
| G2 | 正文搜索不再无脑下载整本刊 | 选「标题+正文」不自动下载；点「开始搜正文」后默认只跑近 3 年 |
| G3 | 检索层有离线保障 | 索引进 SW 缓存，断网仍能跨刊搜标题 |

明确不在本轮目标内：发布日期、每期封面、正文全局倒排索引、服务端搜索、`meta.json` 格式变更。

## 二、现状与实测数据

### 2.1 现状问题

1. **搜索被锁死在当前这一本刊**。`assets/js/app.js` 的 `performSearch()` 取 `getMagState()`，只拿当前刊的 `meta` 做匹配；换刊必须退出重进。
2. **正文搜索默认范围就是「标题+正文」**，且 `performBodySearch()` 的期次循环会一直跑到该刊全部期次加载完（`app.js` 约 484 行）。
3. 主页只用于选刊，**没有检索入口**。

### 2.2 实测数据（本轮量取）

| 项目 | 数值 | 测量方式 |
| --- | --- | --- |
| 三刊文章总数 | 7415 | 三份 `meta.json` 求和 |
| 三刊 `meta.json` 合计 | 1.31 MB（558 + 379 + 377 KB） | 文件大小 |
| 管道式紧凑标题索引（m/y/i/t/u） | 919 KB 原始 / **230 KB gzip** | 三刊全部条目拼接后 gzip -9 |
| 求是正文分片（全量） | 188 期 / **43.3 MB**，均值 236 KB | `data/qs/issues/*.json` |
| 红旗文稿正文分片（全量） | 164 期 / 27.5 MB，均值 172 KB | `data/hqwg/issues/*.json` |
| 党建研究正文分片（全量） | 70 期 / 13.2 MB，均值 194 KB | `data/issues/*.json` |
| 求是近 3 年（2024 起） | 68 期 / 16.2 MB | 同上按年份过滤 |
| 红旗文稿近 3 年 | 68 期 / 12.0 MB | 同上 |
| 党建研究近 3 年 | 33 期 / 6.3 MB | 同上 |

### 2.3 正文倒排索引的实测代价（已否决的路线）

在「求是 2026 年」20 期（182 万字）样本上构建 bigram 倒排索引（无需分词、不引第三方库）：

| 指标 | 样本实测 | 按期数线性外推 |
| --- | --- | --- |
| unique bigram | 120494 | 求是全刊约 113 万 |
| posting 数 | 138615 | 三刊约 290 万 |
| 索引体积（JSON + gzip -6） | 1.8 MB | 三刊约 25–35 MB |

结论：为少下 84 MB 正文要先下 25–35 MB 索引；且两字短词的 posting 覆盖大半刊物，收益有限，三字以上才明显。
因此本轮**不做**正文倒排索引（路线 B 否决），改为「由近及远渐进 + 显式触发」（见 §2.3）。

## 三、已确认的设计决策

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D1 | 走**路线 A**：跨刊标题索引 + 正文由近及远渐进 | 路线 B 索引体积不划算；路线 C（服务端）违背「纯静态零依赖」的项目属性 |
| D2 | 索引**只含标题**（列 `m/y/i/t/u`），不含作者与板块 | 体积更小、语义更单纯；代价是作者/板块只能单刊搜 |
| D3 | 正文搜索**默认不跑**，点「开始搜正文」才跑 | 重操作显式化，避免一次随手搜索换来 43 MB 下载 |
| D4 | 正文搜索**默认近 3 年**，其余按需展开 | 备考关注近三年热点；实测近 3 年为全量的 35%–48% |
| D5 | **跨刊只做标题检索**；正文搜索始终在单刊内 | 跨刊正文需同时拉三刊分片（近 3 年即 34.5 MB），与 D3 的前提冲突 |
| D6 | 「近 3 年」的基准取**该刊数据里的最新年份**，不用浏览器年份 | 避免用户机器日期是 2027 时窗口算错 |
| D7 | 索引是**派生产物**，三份 `meta.json` 仍是唯一权威源 | 避免双份真相；`check_data.py` 断言二者一致 |

## 四、§1 架构与数据形态

### 4.1 新增文件

**`data/search_index.json`** —— 三刊全局标题索引：

```json
{
  "v": "20261101a",
  "cols": ["m", "y", "i", "t", "u"],
  "rows": [
    ["qs", 2019, 1, "本期导读", "http://www.qstheory.cn/dukan/qs/2019-01/01/c_1123924154.htm"],
    ...
  ]
}
```

| 项 | 约定 |
| --- | --- |
| 列义 | `m` 刊物代号（qs / hqwg / djyj）、`y` 年、`i` 期、`t` 标题、`u` 原文 URL |
| 行数 | 7415（= 三刊 `meta.json` 条目之和） |
| 行序 | `qs → hqwg → djyj` 升序 → `y` 降序 → `i` 降序 → 期内沿用 `meta.json` 现有顺序（= 官网目录顺序）。按降序排是为了让前端取到即得「新 → 旧」，不必在客户端再排 |
| 体积 | 预计约 0.9 MB，**断言上限 1.5 MB** |
| 版本 | `v` 字段写索引自身版本（`20261101a`），用于一致性检查与将来按版本重建；**URL 上的缓存破坏参数沿用既有 `dataUrl()`（即 `DATA_VERSION`）**，保持与全站五件套一致，代价是每次发版重下约 0.9 MB，可接受 |

不新增正文索引文件。

### 4.2 生成脚本 `scripts/build_search_index.py`

| 能力 | 行为 |
| --- | --- |
| 默认 | 从三份 `meta.json` 生成 `data/search_index.json` |
| `--check` | 重新生成到内存，与磁盘文件**逐字节比对**，不一致退出码 1 |
| `--self-test` | ≥12 条用例，含 **3 条反向自检**（注入「漏一行」「刊别写错」「顺序被打乱」必须被检出） |
| 体积守卫 | 生成结果 > 1.5 MB 直接报错并拒绝写盘 |

### 4.3 前端新增

- `state.searchIndex`（初始 `null`）+ `loadSearchIndex()`：懒加载，首次跨刊检索时才请求 `data/search_index.json`，走既有 `dataUrl()` 缓存破坏；纳入 SW 缓存。
- `searchAllTitles(query)`：对 `rows` 的 `t` 做小写 `includes` 匹配，返回带 `(mag, y, i, t, u)` 的命中列表。
- `performSearch()` 增加一维 `magScope: 'current' | 'all'`；`current` 分支**完全不变**。

### 4.4 本阶段不动的东西

`data/*/meta.json` 的格式与内容、杂志视图的加载路径、`articles/` 备份、SW 的缓存分键策略、三个专题页。

## 五、§2 交互与界面

### 5.1 杂志内的范围切换

- 搜索框下方新增双态开关 `本刊 / 三刊`，默认「本刊」。
- 选「三刊」时：
  - 结果按刊物分组，组头如「求是 12 篇」「党建研究 3 篇」；
  - 组内按期号新 → 旧（索引行序已保证，见 §4.1）；
  - **只匹配标题**（D2/D5），并在该模式下不显示与正文相关的控件；
  - 搜索框旁提示当前范围，例如「在三刊标题中搜索」。

> **语义差异（必须写清）**：现有单刊「仅标题」实为「标题 + 作者 + 板块」三者任一命中（`articleMatches` 的 `t + a + s` 拼接匹配），而跨刊模式只匹配标题。
> 因此**跨刊命中项必然出现在单刊同词结果中，跨刊结果是单刊结果的子集**——两者不是等价关系，UI 文案不得暗示等价。
- 选「本刊」时保持现状：`标题+正文 / 仅标题 / 仅正文` 三个单选 + `仅有全文` 复选。

### 5.2 首页的全局搜索入口

- 主页标题栏「关于本站」按钮旁加一个放大镜按钮，打开**全屏搜索浮层**，默认「三刊 + 仅标题」。
- **主页三刊封面卡片的版面保持不动**（它是当前视觉最好的一块，不因加搜索而破坏）。

### 5.3 正文搜索：由近及远渐进（D3 + D4）

| 项 | 新行为 |
| --- | --- |
| 默认范围 | 搜索范围默认落在**仅标题**；选「标题+正文」或「仅正文」时**不自动跑** |
| 触发 | 出现「开始搜正文」按钮，按钮上标注预计下载量（如「开始搜正文（近 3 年约 16 MB）」），点击才跑 |
| 顺序 | 期次由「旧 → 新」改为「**新 → 旧**」 |
| 窗口 | 默认只跑该刊数据最新年份起 3 年（求是 2024–2026，68 期 16.2 MB） |
| 继续 | 跑完窗口后，结果条下方出现「继续搜索 2019–2023 年的正文」，点击才继续加载更早的期 |
| 停止 | 加载中提供「停止」，复用既有 `state.searchToken` 机制；停止后保留已命中结果与进度，再次触发从断点续 |
| 提示 | 结果条文案：`共 12 篇 · 本刊 · 正文已加载 68/188 期（2024–2026）` |

### 5.4 结果条目

- 沿用既有 `.results-list` / `.rc-*` 样式与类，不引入新视觉语言。
- 跨刊结果按组平铺（不折叠、不增加交互层级）。
- **单刊结果的排序与呈现保持不变**（仍是 `meta.json` 原有顺序）。本轮不改单刊排序，避免未经确认的行为变更；只有跨刊分组内按新 → 旧（§5.1）。

## 六、§3 数据流与算法

### 6.1 索引生成

```
data/qs/meta.json  ─┐
data/hqwg/meta.json ├─→ build_search_index.py ─→ data/search_index.json
data/meta.json     ─┘
```

行构造 `[mag, y, i, t, u]`；`t` 与 `u` 直接取 `meta.json` 原值（JSON 序列化负责转义）。

### 6.2 前端检索流

```
用户输入
  ├─ magScope = current ──→ 既有 performSearch（ms.meta，本刊）
  └─ magScope = all     ──→ loadSearchIndex()（懒加载）
                             └─→ searchAllTitles(query) → 按 mag 分组 → 渲染
```

`loadSearchIndex()` 失败时：跨刊开关置灰 + 提示「索引不可用，仅可搜本刊」，**不影响本刊搜索、目录、文章页**。

### 6.3 正文检索流（单刊内）

```
performSearch(scope 含正文)
  → 出现「开始搜正文」按钮（不下载）
  → 用户点击
  → listBodyIssues(ms) 改为按 (y, i) 降序
  → 截取 y >= maxYear - 2 的期次
  → 每批 6 期并发加载，每批完成即刷新结果
  → 窗口跑完 → 出现「继续搜索更早年份」→ 点击后从断点续
```

`maxYear` 取该刊 `meta.json` 中最大的 `y`（不读浏览器时间，D6）。

## 七、§4 错误处理与降级

| 情况 | 处理 |
| --- | --- |
| 索引文件缺失 / 加载失败 | 跨刊开关置灰并提示「索引不可用，仅可搜本刊」；本刊功能全部照常 |
| 索引与 `meta.json` 漂移 | 由 `check_data.py` 在提交前拦截；运行时只按索引内容显示 |
| 正文搜索中止 | 保留已命中结果与进度，再次触发从断点续 |
| 近 3 年零命中 | 提示「近 3 年无命中，继续搜索更早年份？」并给出按钮 |
| 索引体积异常 | 构建脚本报错拒绝写盘；`check_data.py` 断言 ≤ 1.5 MB |

## 八、§5 测试与验收

### 8.1 体检脚本

`scripts/build_search_index.py --self-test`：

- 正对照：结构完全合规的三刊 meta → 生成索引零错误；
- 反向自检（3 条，断言到规则编号一级）：漏一行 / 刊别写错 / 顺序被打乱，都必须被抓到。

`scripts/check_data.py` 新增规则：

| 规则 | 断言 |
| --- | --- |
| 索引行数 | = 三刊 `meta.json` 条目数之和（7415） |
| 逐行可寻址 | 每行 `(mag, y, i, u)` 能在对应刊的 `meta.json` 中找到同一条 |
| 无重复 | 索引内 URL 无重复 |
| 体积 | ≤ 1.5 MB |

### 8.2 浏览器目检（桌面 + 窄屏，视觉交付必须截图目检）

1. 三刊模式搜一个跨刊词 → 结果分组正确、组内新 → 旧；
2. 单刊模式搜同一个词 → **跨刊命中的每一项都出现在单刊同词结果中**（跨刊只匹配标题，单刊「仅标题」还匹配作者与板块，故跨刊是子集，见 §5.1）；
3. 选「标题+正文」→ **不自动下载**，出现「开始搜正文」按钮；
4. 点按钮 → 进度条推进、命中上下文显示；
5. 跑完近 3 年 → 出现「继续搜索更早年份」→ 点击后继续；
6. 点「停止」→ 保留已命中结果；
7. **把索引文件临时改名 → 跨刊降级提示正常、本刊搜索与文章页不受影响**；
8. 主页放大镜入口 → 全屏搜索浮层可用；
9. Console 0 错误、0 警告；Network 无失败请求。

### 8.3 离线

索引进 SW 缓存后，断网状态下跨刊标题检索仍可用（需实测）。

### 8.4 兼容性

全部改动只用 CSS 变量、ES5/ES2017 级语法与既有类，`scripts/check_compat.py` 与 `scripts/check_js_comments.py` 必须保持零失败。

## 九、§6 批次划分

| 批次 | 内容 | 依赖 | 风险 |
| --- | --- | --- | --- |
| 一 | 索引脚本 + `data/search_index.json` + 跨刊标题检索 + 范围切换 + 主页搜索入口 | — | 低（新增文件，不改现有数据格式） |
| 二 | 默认仅标题 + 「开始搜正文」显式触发 + 由近及远渐进 + 继续/停止按钮 | 批次一 | 中（改动 `performSearch` 主流程） |
| 三 | 附带小改（独立可回滚）：三个专题页接入密码门、主站 `@media print`、目录期次行去掉重复年份、阅读设置面板滚动自动收起 | — | 低 |

批次三中「三个专题页接入密码门」的实现约束：三个专题页是**自包含静态 HTML**（不引用 `assets/js/app.js`），因此需在每页内联一段与主页一致的门逻辑（`localStorage` 键 `djyj_gate_ok` / `djyj_gate_ts`，12 小时会话），不得引入构建步骤。

每个批次独立提交，并各升一次缓存破坏五件套（`index.html` 四处 `?v=`、`app.js` 的 `DATA_VERSION`、`sw.js` 两处兜底值）。

## 十一、风险与依赖

| 风险 | 应对 |
| --- | --- |
| 索引与 `meta.json` 漂移 | `check_data.py` 强制断言；每月更新数据的流程里加一步重建索引 |
| 索引体积随数据增长 | 体积断言上限 1.5 MB；超限时改为只索引近 N 年并在构建脚本显式告警 |
| `performSearch` 改动波及本刊既有行为 | 批次二单独提交；本刊路径在 `magScope='current'` 下逐行保持不变 |
| SW 缓存了旧索引 | 索引走 `dataUrl()` 带版本号；索引文件变更即随版本失效 |

## 十二、验收标准（Definition of Done）

1. 主页放大镜与杂志内「三刊」开关都能完成跨刊标题检索，结果分组正确、期号新 → 旧；
2. 单刊检索行为与改动前一致（有前后对照截图）；
3. 正文搜索默认不下载，点「开始搜正文」后才跑，且默认窗口为该刊最新年份起 3 年；
4. 「继续搜索更早年份」与「停止」均可用，停止后结果与进度保留；
5. 索引缺失时跨刊降级提示正常，本刊功能无异常；
6. `build_search_index.py --self-test` ≥12 条含 3 条反向自检全通过；
7. `check_data.py` 新增四条断言全通过；
8. `check_compat.py` / `check_js_comments.py` / `check_sw_navigate.py` / `check_reading_width.py` 全部零失败；
9. 桌面与窄屏各一轮截图目检，Console 0 错误；
10. 三批各自独立提交，提交信息诚实标注验证范围与「已实现但未独立审查」。
